```
stored win → 내부 weight = {win, 1'b0} + 1 = 2·win + 1
```

- activation은 zero-extend: `{1'b0, din}`

### Section B

**B1. Encoder — 왜 `else dout = 2'b00;`이 필수인가?**

```verilog
always @(*) begin
    if(din0==1 && ...) dout = 2'b00;
    else if(...) dout = 2'b01;
    ...
    else dout = 2'b00;   // ← 이 줄이 필수인 이유
end
```

- `always @(*)`는 **조합 회로**. 모든 입력 조합에 대해 `dout`이 **반드시 대입**되어야 함.
- `else`가 없으면: 입력이 one-hot이 아닐 때(0000, 1100 등) `dout`에 새 값이 안 들어가고 **이전 값을 유지**하려 함 → **의도치 않은 latch** 추론.
- latch는 조합 인코더에 불필요·위험(타이밍, 시뮬레이션/합성 불일치).
- `else dout = 2'b00;`로 **default를 명시**하면 latch가 안 생기고, invalid 입력은 `00`으로 안전하게 처리.

**B1 연계 — MAC / din·win (Day 14 기준 재구성)**

강의 TB 가정: win 저장값=0 → 내부 weight=`2·0+1=1`, din 채널이 모두 같은 값 k이면

\[
mac\_o = \sum_{i=0}^{15} 1 \cdot k = 16k
\]

1) **(대표 답)** win의 각 8bit = 0, din의 각 8bit = cycle에 따라 1,2,…  
   → 변환 후 weight 전부 1, activation = din.

2) “unsigned / radix” 표현이 복구로 깨짐.  
   요지: **signed 확장·`2w+1` 변환**을 쓰므로, “그냥 저장된 hex를 그대로 곱한다”고 보면 오답.

3) **mac_kern 용도:** 채널 방향 MAC 결과를 **필터(커널) 방향 partial sum**으로 누적.  
   - 1x1: 매 사이클 출력  
   - 3x3: 9번 누적 후 1출력 (예: 720)

4) **srl / shifter:** `bias_shifter` / `act_shifter` — bias·activation **quantization을 위한 산술/논리 시프트** (고정소수점 스케일 맞춤).  
   (복구본 `srl_shift` ≈ 이 계열로 보는 것이 타당)

**B2. Demux / Apriori**  
복구 혼선 가능성 큼. 수업 본선은 **채널 demux·버스 decode(AHB HSEL)** 쪽.  
Apriori는 데이터마이닝 — 이 과목 우선순위 낮음.

**B3. Amdahl’s law**

\[
S_{\text{latency}}(N)=\frac{1}{(1-p)+\frac{p}{N}}
\]

- \(p\): 개선 대상이 차지하는 **원래 시간 비율**
- \(N\): 그 부분의 가속비  
- 순차 구간 \((1-p)\)가 상한 → 코어만 늘려도 한계

**강의 수치 예**
| | Baseline | DMA×4 | Layer3×4 |
|--|----------|-------|----------|
| Total (us) | 3930 | 3789 | 2666 |
| Speedup | 1.00 | **1.037** | **1.474** |

→ **비중이 큰 Layer3**를 가속하는 편이 DMA 가속보다 이득.

## 3. 예상 기출 + 풀이

### 예상 A (빈칸)

**Q1.** Boolean algebra를 정립한 영국 수학자는?  
→ **George Boole** (1854 *Laws of Thought*). Shannon은 이를 회로에 적용.

**Q2.** RISC-V base integer ISA 이름은? 왜 freeze인가?  
→ **RV32I**. 컴파일러/소프트웨어 스택 호환을 위해 base는 변하지 않음. 확장은 모듈로 추가.

**Q3.** AHB에서 Slave가 전송 완료를 알리는 신호는?  
→ **HREADY** (추가로 HRESP).

**Q4.** CNN에서 Ti=16, To=16일 때 3x3 한 레이어 weight word 수는?  
→ \((Ti·To·9)/N = 16·16·9/16 = 144\).

**Q5.** FSD/CNN에서 convolution이 Nested loop로 표현될 때 흔히 말하는 loop 개수는?  
→ **seven-nested for loop** (Day 18).

---

### 예상 B (계산·코드)

**Q6.** win 전 채널=0, din 전 채널=5, conv1x1 한 사이클 mac 출력은?  
→ weight=1, \(16×5=80\).

**Q7.** 같은 조건으로 din이 1~9까지 9사이클, conv3x3 최종 acc는?  
→ \(16(1+…+9)=16·45=720\).

**Q8.** mac.v pipeline delay 5, mac_kern 1x1 추가 1 → vld delay?  
→ **6**. 3x3는 누적 9 → **14**.

**Q9.** 전체 중 40%만 4배 고속화. Speedup?  
→ \(S=1/(0.6+0.4/4)=1/(0.6+0.1)=1/0.7≈1.43\).

**Q10.** Layer1에서 num_ops=9 < Ti=16이면?  
→ din[9]…din[15]=0 (또는 해당 mul 무효). utilization 낭비, 출력에는 영향 없음(Day 17).

**Q11.** FSM에서 conv3x3 시 col을 매 사이클 올리면?  
→ 픽셀당 9 MAC 전에 좌표가 이동 → 출력 수 부족 → **layer_done 미발생/타임라인 이상**.  
→ `pix_idx==8`일 때만 pixel advance.

**Q12.** Encoder를 `always @(posedge clk)`로 바꾸면?  
→ 동기화되어 1클럭 지연. 조합 인코더 규격과 달라짐(불필요 레지스터).

### 예상 C (서술)

**Q13.** Turing Machine 구성 요소 4가지 + 의의  
→ 무한 테이프, Head, 상태 레지스터, 상태전이 테이블.  
의의: 계산가능성의 이론적 토대, 현대 컴퓨터 모델.

**Q14.** Turing Test 절차와 한계  
→ 평가자–인간–기계 텍스트 대화, 구분 못하면 통과.  
한계: 언어·속임 가능, 엄밀히 통과 사례 없음(강의 표현).

**Q15.** CNN Accelerator에서 CPU 대비 가속 이유  
→ CPU는 ALU/mul 소수; CNN은 MAC 어레이로 대량 병렬.  
효율(성능/전력/면적)이 “accelerator”의 핵심 지표.

**Q16.** 국방 반도체의 특징 3가지  
→ 초소량·고단가, 장기 공급, 신뢰성>단가, 극한 환경(예: hypersonic) 시험.

**Q17.** HGV vs 탄도미사일  
→ 탄도: 예측 가능한 포물선. HGV: 활공+기동, 저고도·변칙 → 추적/요격 난이도↑, IMU·공력제어 중요.

**Q18.** AHB로 RISC-V가 CNN IP를 제어하는 흐름  
→ 레지스터 write(FRAME_SIZE, LAYER_CONFIG, START) → FSM 동작 → LAYER_DONE poll → 다음 레이어 base address 갱신.
